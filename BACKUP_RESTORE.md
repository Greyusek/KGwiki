# Резервное копирование и восстановление KGwiki

## Зачем это нужно
Перед обновлением приложения обязательно делайте резервную копию. Это защищает данные пользователей и загруженные файлы от случайной потери.

## Какие данные нужно защищать
В резервной копии должны быть:
- Пользователи (учетные записи, роли).
- Активности (activities).
- Комментарии.
- Обратная связь (feedback).
- Планы (plans).
- Загруженные файлы (MinIO).
- Материалы по внешним ссылкам (записи в БД о них).
- Секреты и конфигурация из `.env`.

## Где хранятся резервные копии
Скрипт создает папки в каталоге проекта:

- `backups/YYYY-MM-DD_HH-MM-SS/`

Пример:
- `backups/2026-04-30_15-30-00/`

## Как сделать резервную копию
Из корня проекта выполните:

```bash
./scripts/backup.sh
```

Скрипт сохраняет:
- `postgres.dump` — дамп PostgreSQL.
- `minio-data.tar` — архив файлов из MinIO.
- `.env` — копия (если файл существует).
- `docker-compose.yml` — снимок текущего compose.
- `README.txt` — описание содержимого бэкапа.

## Как восстановить данные
Восстановление перезапишет текущие данные БД и MinIO.

Пример команды:

```bash
./scripts/restore.sh backups/2026-04-30_15-30-00
```

Что делает скрипт:
1. Просит подтверждение перед разрушительными действиями.
2. Останавливает `app` и `nginx`.
3. Поднимает `db` и `minio`.
4. Пересоздает БД `kgwiki` и восстанавливает дамп.
5. Очищает `/data` MinIO и восстанавливает файлы из архива.
6. Запускает весь стек обратно.
7. Показывает, как вручную восстановить `.env` при необходимости.

## Рекомендуемая безопасная процедура обновления
1. Создать резервную копию:
   ```bash
   ./scripts/backup.sh
   ```
2. Обновить код (например, `git pull`).
3. Пересобрать и запустить:
   ```bash
   docker compose up -d --build
   ```
4. Проверить после обновления:
   - вход в систему (login),
   - страницу активностей,
   - загрузку файлов,
   - страницу планов.

## Опасные команды (использовать только при полном понимании последствий)
**Не запускайте** эти команды в обычной работе:

- `docker compose down -v`
- `docker volume rm ...`
- `docker system prune --volumes`

Эти команды могут удалить тома с данными PostgreSQL и MinIO.

## Аварийное восстановление
Если после обновления что-то пошло не так:
1. Остановите изменения в системе (не загружайте новые файлы, не редактируйте данные).
2. Выберите последнюю корректную резервную копию в `backups/`.
3. Выполните восстановление:
   ```bash
   ./scripts/restore.sh backups/<нужная_папка>
   ```
4. Проверьте вход, активности, файлы, планы.
5. Если нужно вернуть секреты/URL, вручную восстановите `.env` из бэкапа.
